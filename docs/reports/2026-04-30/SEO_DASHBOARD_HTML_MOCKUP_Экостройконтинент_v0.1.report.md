## Реализованные зоны экрана

В мокапе реализованы:

- верхняя шапка раздела "Видимость" с периодом 7 / 28 / 90 дней;
- бейджи состояния источников: Яндекс Метрика, Яндекс Вебмастер, Google Search Console, first-party события;
- главный блок "Что делать сейчас" с 4 приоритетными действиями;
- обзорные метрики: визиты, органика, показы, клики, CTR, контактные действия, лиды, конверсия визит -> контакт;
- рабочая таблица страниц SEO Manager с проблемами, proof path и статусами рекомендаций;
- карточка выбранной страницы с URL, SEO-полями, индексированием, sitemap/canonical и диагностикой;
- semantic click map без пиксельной heatmap;
- backlog рекомендаций со статусами `new`, `accepted`, `in_progress`, `done`, `dismissed`;
- блок "Копилот" как контекстный помощник с безопасными кнопками и примером ответа;
- блок источников трафика с Yandex-first порядком;
- панель состояния источников данных;
- примеры `not_configured`, `stale`, `not_ready` и unmapped URL warning.

## Решения по визуальной иерархии

Экран сделан action-first: сначала показаны приоритетные действия, затем метрики, таблица страниц, detail выбранной страницы, semantic click map, копилот, источники и диагностика.

Яндекс Метрика и Яндекс Вебмастер визуально поставлены первыми в шапке, источниках и состоянии интеграций. First-party events показаны как обязательная внутренняя основа для контактных действий и связи с сущностями сайта.

Метрики не оформлены как декоративная отчётность: под каждой цифрой есть пояснение по свежести, сравнению, ограничениям или готовности домена данных.

Копилот не сделан свободным главным чатом. Он представлен как контекстная панель с ограниченными действиями: объяснение, гипотеза, черновик рекомендации, запрос владельцу и сравнение до/после. В тексте ответа разделены факты, гипотезы, действия и ограничения.

Все числовые показатели, URL, revision id, статусы, даты проверок, источники, рекомендации, diagnostic labels и пример ответа копилота являются фейковыми, но реалистичными mock data.

## UI integrity check

Статус: pass.

Экран решает задачу SEO-специалиста: быстро увидеть, где теряются показы, клики, контактные действия и proof path, и выбрать следующее действие.

Основное действие пользователя: открыть проблемную страницу или создать/обновить рекомендацию для проверки.

Показаны пользовательские состояния: `ok`, `not_configured`, `not_ready`, `stale`, unmapped URL warning, lead domain unavailable. Для интерактивных элементов есть видимые состояния hover/focus и `aria-pressed` у переключателей.

Граница UI соблюдена: мокап только отображает фейковые данные и визуальные переключатели, не содержит доменной логики, API-вызовов, мутаций или интеграций.

Обратная связь на визуальные действия есть: выбор периода меняет бейдж периода, кнопки копилота меняют пример ответа. Все действия являются демонстрационными.
